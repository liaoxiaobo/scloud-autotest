# 镜像服务可自动化场景整理

来源文件：`C:\Users\Administrator\Downloads\曙光云Stack-用例-镜像服务.xlsx`

## 结论

工作簿中“用例”sheet 共识别 143 条镜像服务相关用例。按当前 Python + Playwright + Pytest 框架能力评估，建议拆成 14 类可自动化场景：

- P0：优先自动化页面与短链路场景，稳定、执行快、对环境依赖少。
- P1：自动化完整业务链路，依赖镜像、项目、存储池等 fixture，可作为回归主体。
- P2：自动化但标记 `slow` 或环境专属，包含 VNC/系统验证、裸金属、安全云、国密加密、多格式矩阵、异常状态注入。

当前仓库已有可复用基础：

- `sugon_web/pages/compute/image.py`：已有镜像创建/删除的少量封装，但镜像服务专属 Page Object 仍需补充。
- `sugon_web/common/remote/scli.py`：已有 `glance_image_create`、`glance_image_delete`、`wait_image_deleted`、镜像文件下载能力。
- `sugon_web/pages/compute/ecs/ecs_create.py`：已有云服务器创建时选择镜像/ISO/快照/云硬盘来源的能力。
- `sugon_web/testcase/compute/conftest.py`：已有 `image` fixture，可扩展成镜像服务专属资源生命周期 fixture。

## 自动化筛选规则

可直接纳入自动化的场景：

- UI 可以稳定定位：列表、详情、弹窗、按钮状态、提示文案、字段回显。
- 资源可以通过 fixture 准备和清理：镜像、存储池、项目、云服务器、安全组等。
- 预期可以通过 UI + SSH 后端命令验证：`scli image list/show/delete`、`glance image-show`、实例网络/磁盘/CPU 信息。

需要降级为 slow 或环境专属的场景：

- 依赖大镜像、多格式镜像、快速上传客户端、VNC 登录、裸金属、安全云、国密密钥、异常存储池或数据库状态注入。
- 这类不是不能自动化，而是不适合放默认回归；建议加 `@pytest.mark.slow`，并用环境探测决定是否 skip。

## 推荐落地顺序

1. 新增镜像服务 Page Object 能力：列表搜索、进入详情、读取详情字段、打开新建/导入/上传/修改/共享/同步/删除弹窗、断言按钮状态。
2. 新增镜像 fixture：`image` 保留通用创建；补 `private_image`、`shared_image`、`encrypted_image`、`image_with_storage_pool`、`clean_images`。
3. 先实现 P0：页面校验、详情字段、保护状态、下载入口。验证目标是稳定通过默认 `pytest sugon_web/testcase/`。
4. 再实现 P1：CRUD、导入、上传、共享、存储池同步、使用镜像创建 ECS。验证目标是 UI 与 `scli/glance` 一致。
5. 最后实现 P2：多格式、裸金属、安全云、国密、异常注入。统一加 `slow` 和环境 skip。
