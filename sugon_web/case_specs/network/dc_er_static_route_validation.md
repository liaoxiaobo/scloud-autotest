# 测试用例：云专线DC-ER类型HA静态路由生效性验证

## 基本信息

- 用例编号：420687
- 所属产品：曙光云Stack
- 一级模块：网络
- 二级模块：云专线DC

## 适配范围

### 存储适配

- 该用例不支持的存储：无

### 架构/节点限制

- 架构限制：无
- 节点要求：无

## 前置条件

1. VPC+ECS环境
   - 虚拟私有云名称：`er1_dc_vpc1`，网段 `13.34.34.0/24`
   - 在该VPC下创建弹性云服务器 `vm1`，并绑定MFIP
   - **本资源由 fixture 自动创建和清理**

2. HA类型企业路由器
   - 名称：`er1-dc-ha-autotest`
   - 开启HA
   - 将前置条件1中的VPC添加为连接
   - **本资源由测试脚本创建和清理**

3. HA类型物理连接
   - 名称自定义
   - 运营商：联通
   - 端口类型：10GE 单模光口
   - 开启HA
   - 审批通过，VLAN号固定为205
   - **本资源由测试脚本创建和清理**

## 测试步骤

### 场景1：ER类型+HA-静态路由生效性验证（用例420687）

#### 步骤1：创建虚拟网关

- 操作：进入云专线DC模块，点击虚拟网关子菜单，点击新建按钮
- 子步骤：
  1. 名称字段，输入自定义字符串 `er_virtual_gateway`
  2. 关联模式字段，选择**企业路由器**
  3. 企业路由器字段，选择前置条件2中准备的ER实例 `er1-dc-ha-autotest`
  4. 其它信息保持默认值
  5. 点击立即创建
- 预期：
  - 可以正常进入虚拟网关模块
  - 可以弹出虚拟网关新建页面
  - 可以正常输入名称
  - 可以正常选择关联模式为企业路由器
  - 可以选择到预置的企业路由器实例
  - 可以正常提交创建

#### 步骤2：验证虚拟网关列表

- 操作：页面跳转虚拟网关列表，验证列表页虚拟网关信息
- 预期：
  - 可以查看到刚刚创建的虚拟网关
  - 名称为步骤1中输入的名称
  - 状态为运行中
  - 资源名称为预置的企业路由器名称 `er1-dc-ha-autotest`

#### 步骤3：创建虚拟接口

- 操作：左侧导航点击虚拟接口，进入云专线的虚拟接口模块，点击新建
- 子步骤：
  1. 名称字段，输入自定义字符串 `virtual_interface`
  2. 物理连接字段，选择前置条件3中预置的物理连接
  3. 虚拟网关字段，选择步骤1中创建的虚拟网关 `er_virtual_gateway`
  4. 本端网关（云端侧），固定值，输入 `11.22.0.2/24`
  5. 远端网关（用户侧），固定值，输入 `11.22.0.3/24`
  6. 路由模式，选择**静态路由**
  7. 远端子网字段，固定值，输入 `123.12.0.0/24`
  8. 本端子网字段，输入前置条件1中准备的VPC的CIDR信息，即 `13.34.34.0/24`
  9. 其它信息保持默认值，点击立即创建
- 预期：
  - 可以正常进入虚拟接口模块，点击新建可以正常弹窗
  - 可以正常输入名称
  - 可以正常选择物理连接
  - 可以正常选择虚拟网关
  - 可以正常输入本端网关
  - 可以正常输入远端网关
  - 可以选择静态路由模式
  - 可以正常输入远端子网字段
  - 可以正常输入本端子网字段
  - 可以正常提交创建虚拟接口

#### 步骤4：验证虚拟接口状态

- 操作：页面跳转虚拟接口列表，等待30秒后，验证列表页虚拟接口信息，等待期间每隔10秒点击右上角的刷新按钮更新虚拟接口的状态
- 预期：
  - 可以正常创建，创建后列表可以正常显示新增的虚拟接口记录
  - 名称为步骤3中输入的名称
  - 状态为运行中

#### 步骤5：在VPC中添加自定义路由

- 操作：进入虚拟私有云模块，进入VPC详情页的路由表tab，点击新建按钮添加自定义路由
- 子步骤：
  1. IPv4版本
  2. 目的地址为 `123.12.0.0/24`
  3. 下一跳类型为**企业路由器**
  4. 下一跳为前置条件2预置的ER实例 `er1-dc-ha-autotest`
  5. 点击确定
- 预期：
  - 自定义路由表规则创建成功
  - 列表存在目的地址为 `123.12.0.0/24`、下一跳类型为企业路由器、下一跳为预置的ER实例的自定义路由

#### 步骤6：在ER路由表中添加规则

- 操作：进入企业路由器模块，列表页点击ER名称进入详情页，点击路由表tab，点击新建路由表规则
- 子步骤：
  1. 目的地址为 `123.12.0.0/24`
  2. 下一跳类型为**云专线**
  3. 连接字段选择下拉列表对应的云专线的连接名称
  4. 下一跳字段选择前置条件3预置的云专线物理连接的名称
  5. 点击确定
- 预期：
  - 可以正常打开企业路由器详情
  - 可以正常打开路由表tab页
  - 路由表规则创建成功
  - 列表存在目的地址为 `123.12.0.0/24`、下一跳类型为云专线、下一跳为预置的云专线物理连接的自定义路由

#### 步骤7：SSH验证路由生效

- 操作：使用 `ssh_vm` fixture 连接 `vm1`，执行如下操作
- 子步骤：
  1. 在弹性云服务器 `vm1` 的后台，执行命令：`ping -c 4 123.12.0.10`
  2. 验证是否可以ping通，ping 4次全通，才算ping通
  3. ping的明细需要打印出来，并输出到日志中
- 预期：
  - vm1可以正常ssh连接
  - vm1对 `123.12.0.10` 执行ping请求时，均可以正常ping通
  - 需要断言ping的结果（返回码为0，且输出包含 "4 packets transmitted, 4 received" 或 "0% packet loss"）

## ⚠️ 实现注意事项

### 1. SSH操作强制约束

- 若测试步骤或前置条件中需要SSH到服务器后台或虚拟机后台执行命令，**必须**调用 `sugon_web/common/ssh.py` 中封装好的公共方法
- 禁止在测试代码中直接使用 `paramiko`、`subprocess` 等方式建立SSH连接
- 推荐使用fixture：
  - `ssh_vm` fixture：通过跳板机连接虚机的SSH会话
  - `ssh_host` fixture：直接SSH连接目标主机（不经过跳板机）

### 2. Fixture强制约束

- 实现测试步骤或前置条件的自动化脚本前，**必须**阅读 `sugon_web/case_specs/fixtures_index.md`
- 查阅fixture强制约束和速查表，确认框架中是否已有可复用的fixture
- **禁止**针对已有的fixture进行重复封装

### 3. 可复用Fixture参考

根据 `fixtures_index.md`，本用例可能涉及的fixture：

- `vpc` fixture：创建VPC（支持count参数批量创建），返回name、subnet_name、cidr
- `vm` fixture：创建虚机（支持count参数批量创建，自动绑定MFIP），若引用vpc则自动复用其网络和子网
- `vpc_page` fixture：虚拟私有云页对象，用于VPC路由表操作
- `dc_page` fixture：云专线DC页对象，用于物理连接/虚拟网关/虚拟接口操作
- `er_page` fixture：企业路由器页对象，用于ER创建/连接/路由表操作
- `ssh_vm` fixture：用于SSH连接虚拟机执行ping验证

### 4. 虚拟网关ER关联模式

- 现有 `virtual_gateway_create` 方法已支持 `association_mode` 参数，但当前实现仅处理VPC选择逻辑
- 当 `association_mode="er"` 时，需要选择企业路由器而非虚拟私有云
- 需要扩展页面对象方法以支持ER关联模式的完整流程

### 5. 后台命令执行规范

- 所有需要后台长期运行的命令，**必须**使用 `nohup` 命令并在末尾添加 `&` 符号
- 示例：`nohup <command> > /dev/null 2>&1 &`

### 6. ER路由表下一跳类型与下一跳字段区分

- **下一跳类型**和**下一跳**是完全不同的两个字段，不要弄混
- 下一跳类型是el-select，选项为：`虚拟私有云VPC`、`VPN`、`NAT`、`云专线`、`云防火墙CFW`、`企业路由器`等
- 下一跳是在选择连接后动态加载的另一个el-select
- 定位"下一跳"字段时，必须使用精确文本匹配 `exact=True`，避免匹配到"下一跳类型"

## 清理数据

### ⚠️ 清理顺序强制要求

本用例的测试数据清理流程**必须**按照如下顺序执行：

1. 删除虚拟接口 `virtual_interface`
2. 删除虚拟网关 `er_virtual_gateway`
3. 注销物理连接 `physical_connection`
4. 删除虚拟私有云 `er1_dc_vpc1` 下添加的自定义路由规则
5. 删除企业路由器 `er1-dc-ha-autotest` 下添加的所有连接
6. 删除企业路由器实例 `er1-dc-ha-autotest`
7. 删除弹性云服务器 `vm1`
8. 删除虚拟私有云 `er1_dc_vpc1`

### 清理注意事项

- 清理顺序不可颠倒，必须严格按照上述顺序依次执行
- 如果在清理过程中某一步骤失败，需先解决该步骤的问题后再继续后续清理
- 每个清理步骤完成后应验证清理成功，再执行下一个清理步骤
- VM和VPC由fixture的teardown机制自动完成（步骤7、8）
- 需要在finally块中执行清理，确保即使测试失败也能清理资源
