## 测试步骤

### 场景1：物理连接-新建功能测试（用例418598）

#### 步骤1：进入物理连接页面

- 操作：登录云平台后，依次点击：资源中心 -> 网络 -> 云专线DC -> 物理连接，进入"物理连接"页面
- 预期：
  - 页面正常跳转，无报错出现
  - 物理连接列表页可以正常显示
  - 页面右上角显示"新建"按钮

#### 步骤2：打开新建弹窗并填写信息

- 操作：点击列表页"新建"按钮，打开"新建物理连接"弹窗，按如下要求填写信息
- 子步骤：
  1. 物理连接名称：输入 `physical_connection`
  2. 运营商：选择"联通"（对应值 `unicom`）
  3. 端口类型：选择"10GE 单模光口"
  4. 联系人姓名：输入 `张三`
  5. 联系人手机：输入 `13805403159`
  6. 联系人Email：输入 `ll@sugon.com`
  7. HA选项：如弹窗中显示HA开关，则将其从默认开启状态切换为关闭
- 预期：
  - 弹窗正常打开，标题为"新建物理连接"
  - 各输入框可以正常输入，输入后字段值在输入框中显示准确
  - 下拉框可以正常选择，字段值在输入框中显示准确
  - HA默认值显示准确（如显示则为开启状态），可以正常关闭

#### 步骤3：提交创建

- 操作：点击弹窗中的"立即创建"按钮
- 预期：
  - 弹窗关闭，页面自动跳转到物理连接列表页
  - 列表中可以看到新创建的物理连接记录
  - 该记录的状态为"办理中"

#### 步骤4：验证详情页信息

- 操作：在列表页中，点击新创建的物理连接实例名称，进入详情页面
- 预期：
  - 详情页可以正常打开
  - 详情展示的信息与创建时填写的信息一致
  - 字段"HA"显示为"关闭"

## ⚠️ 实现注意事项

### 1. SSH操作强制约束

- 本用例不涉及SSH后台操作

### 2. Fixture强制约束

- 实现测试步骤或前置条件的自动化脚本前，**必须**阅读 `sugon_web/case_specs/fixtures_index.md`
- 查阅fixture强制约束和速查表，确认框架中是否已有可复用的fixture
- **禁止**针对已有的fixture进行重复封装

### 3. 可复用Fixture参考

根据 `fixtures_index.md`，本用例可能涉及的fixture：

- `page` fixture：提供浏览器页面实例
- 云专线DC暂无专用页面对象fixture，需在测试模块的 `conftest.py` 中新增 `dc_page` fixture（导航到云专线DC服务）

### 4. 页面交互注意事项

- **项目选择对话框**：进入物理连接页面时，可能弹出"请选择项目"对话框，需先处理该对话框后再进行后续操作
- **HA字段条件渲染**：HA开关字段根据后端策略配置（`policy_document`）条件渲染，如策略未开启则该字段不显示，此时无需操作HA开关，后端默认提交 `ALONE`
- 运营商选项对应值：`telecom`（电信）、`mobile`（移动）、`unicom`（联通）、`other`（其他）
- 端口类型选项：`1GE 单模光口`、`10GE 单模光口`、`40GE 单模光口`、`100GE 单模光口`
- 状态映射：`CREATED` → "办理中"、`DONE` → "办结"、`REJECTED` → "驳回"

### 5. 断言策略

- 列表页断言：验证新创建记录的名称、状态字段
- 详情页断言：验证各字段值与输入值一致，特别是HA字段显示为"关闭"
