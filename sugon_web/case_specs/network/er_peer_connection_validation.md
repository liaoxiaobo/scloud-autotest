# 测试用例：企业路由器-对等连接-生效性验证

## 基本信息

- 用例编号：412951, 1412951
- 所属产品：曙光云Stack
- 一级模块：网络
- 二级模块：企业路由器

## 适配范围

### 存储适配

- 该用例不支持的存储：无

### 架构/节点限制

- 架构限制：无
- 节点要求：无

## 前置条件

1. 已预置虚拟私有云 `er1_vpc1`，网段 `173.3.3.0/24`，并在该VPC下预置一台弹性云服务器 `vm1`
2. 已预置虚拟私有云 `er1_vpc2`，网段 `174.4.4.0/24`，并在该VPC下预置一台弹性云服务器 `vm2`
3. 场景1（HA2HA）：已预置两个HA类型的企业路由器 `er1-ha-autotest` 和 `er2-ha-autotest`
4. 场景2（noHA2noHA）：已预置两个非HA类型的企业路由器 `er1-noha-autotest` 和 `er2-noha-autotest`

## 测试步骤

### 场景1：HA2HA-ER对等连接生效性验证（用例412951）

#### 步骤1：进入企业路由器列表页

- 操作：登录云平台后，依次点击：资源中心 -> 网络 -> 企业路由器
- 预期：可以正常打开企业路由器列表页

#### 步骤2：生成ER1授权码

- 操作：在ER列表页，点击 `er1-ha-autotest` 操作栏的"生成授权码"按钮，记录生成的授权码为 `er1_code`，点击取消按钮关闭弹窗
- 预期：可以正常生成授权码

#### 步骤3：生成ER2授权码

- 操作：返回ER列表页，点击 `er2-ha-autotest` 操作栏的"生成授权码"按钮，记录生成的授权码为 `er2_code`，点击取消按钮关闭弹窗
- 预期：可以正常生成授权码

#### 步骤4：ER1添加ER连接

- 操作：ER列表页，点击 `er1-ha-autotest` 操作栏的"管理连接"按钮，进入连接tab后点击"添加连接"按钮，按如下内容输入：
  - 名称：按常规输入，如 `er1-er2-conn`
  - 连接类型：选择"企业路由器"
  - 授权码：输入步骤3记录的 `er2_code`
  - 其它字段保持默认值，点击确定
- 预期：可以正常提交，添加连接成功

#### 步骤5：等待并验证ER1连接

- 操作：返回连接列表，等待约1分钟，期间每隔20秒点击刷新按钮，1分钟后在列表确认新增的连接是否存在
- 预期：列表可以正常显示新提交的连接，名称为 `er1-er2-conn`，状态为运行中，连接类型为企业路由器

#### 步骤6：ER2添加ER连接

- 操作：返回ER列表页，点击 `er2-ha-autotest` 操作栏的"管理连接"按钮，进入连接tab后点击"添加连接"按钮，按如下内容输入：
  - 名称：按常规输入，如 `er2-er1-conn`
  - 连接类型：选择"企业路由器"
  - 授权码：输入步骤2记录的 `er1_code`
  - 其它字段保持默认值，点击确定
- 预期：可以正常提交，添加连接成功

#### 步骤7：等待并验证ER2连接

- 操作：返回连接列表，等待约1分钟，期间每隔20秒点击刷新按钮，1分钟后在列表确认新增的连接是否存在
- 预期：列表可以正常显示新提交的连接，名称为 `er2-er1-conn`，状态为运行中，连接类型为企业路由器

#### 步骤8：ER1路由表添加规则

- 操作：返回ER列表页，点击 `er1-ha-autotest` 操作栏的"管理路由表"按钮，进入路由表tab后点击"新建路由表规则"按钮，按如下内容输入：
  - 目的地址：`174.4.4.0/24`（er1_vpc2的网段）
  - 下一跳类型：选择"企业路由器"
  - 连接：选择连接 `er1-er2-conn`
  - 下一跳：选择企业路由器 `er2-ha-autotest`
  - 其它字段保持默认值，点击确定
- 预期：可以正常提交，路由规则添加成功

#### 步骤9：等待并验证ER1路由规则

- 操作：返回路由表列表，等待约1分钟，期间每隔20秒点击刷新按钮，1分钟后在列表确认新增的路由规则是否存在
- 预期：列表可以正常显示新提交的路由规则

#### 步骤10：ER2路由表添加规则

- 操作：返回ER列表页，点击 `er2-ha-autotest` 操作栏的"管理路由表"按钮，进入路由表tab后点击"新建路由表规则"按钮，按如下内容输入：
  - 目的地址：`173.3.3.0/24`（er1_vpc1的网段）
  - 下一跳类型：选择"企业路由器"
  - 连接：选择连接 `er2-er1-conn`
  - 下一跳：选择企业路由器 `er1-ha-autotest`
  - 其它字段保持默认值，点击确定
- 预期：可以正常提交，路由规则添加成功

#### 步骤11：等待并验证ER2路由规则

- 操作：返回路由表列表，等待约1分钟，期间每隔20秒点击刷新按钮，1分钟后在列表确认新增的路由规则是否存在
- 预期：列表可以正常显示新提交的路由规则

#### 步骤12：VPC1添加自定义路由

- 操作：进入VPC模块，列表点击 `er1_vpc1` 进入VPC详情，在"路由表"tab下添加自定义路由：
  - 版本：ipv4
  - 目的地址：`174.4.4.0/24`
  - 下一跳类型：企业路由器
  - 下一跳：`er1-ha-autotest`
- 预期：自定义路由添加成功，根据目的地址断言自定义路由列表是否存在新添加的路由规则

#### 步骤13：VPC2添加自定义路由

- 操作：返回VPC列表页，列表点击 `er1_vpc2` 进入VPC详情，在"路由表"tab下添加自定义路由：
  - 版本：ipv4
  - 目的地址：`173.3.3.0/24`
  - 下一跳类型：企业路由器
  - 下一跳：`er2-ha-autotest`
- 预期：自定义路由添加成功，根据目的地址断言自定义路由列表是否存在新添加的路由规则

#### 步骤14：验证vm1到vm2的连通性

- 操作：通过 `ssh_vm` fixture 连接虚机 `vm1`（使用 `ssh_vm.connect(vm1_mfip)` 建立SSH连接），执行如下命令：
  ```bash
  ping -c 4 <vm2_ip>
  ```
  其中 `<vm2_ip>` 为虚机 `vm2` 的IP地址
- 预期：可以正常SSH连接到vm1，ping命令执行成功，ping 4次全通，断言ping结果中 packet loss 为 0%

#### 步骤15：验证vm2到vm1的连通性

- 操作：通过 `ssh_vm` fixture 连接虚机 `vm2`（使用 `ssh_vm.connect(vm2_mfip)` 建立SSH连接），执行如下命令：
  ```bash
  ping -c 4 <vm1_ip>
  ```
  其中 `<vm1_ip>` 为虚机 `vm1` 的IP地址
- 预期：可以正常SSH连接到vm2，ping命令执行成功，ping 4次全通，断言ping结果中 packet loss 为 0%

### 场景2：noHA2noHA-ER对等连接生效性验证（用例1412951）

> 本场景与场景1操作完全一致，区别仅在于企业路由器类型为非HA（`er1-noha-autotest` 和 `er2-noha-autotest`）。

#### 步骤1-15：

- 操作：同场景1步骤1-15，将 `er1-ha-autotest` 替换为 `er1-noha-autotest`，将 `er2-ha-autotest` 替换为 `er2-noha-autotest`
- 预期：同场景1

## 清理数据

### 清理顺序强制要求

测试数据清理流程**必须**按照如下顺序执行：

1. 删除两个VPC下的自定义路由规则
2. 删除ER实例下的所有连接
3. 删除企业路由器实例
4. 删除弹性云服务器vm1和vm2
5. 删除虚拟私有云er1_vpc1和er1_vpc2

### 清理注意事项

- 清理顺序不可颠倒，必须严格按照上述顺序依次执行
- 如果在清理过程中某一步骤失败，需先解决该步骤的问题后再继续后续清理
- 每个清理步骤完成后应验证清理成功，再执行下一个清理步骤
- 测试数据标记为"不可复用"，测试完成后需要彻底清理所有资源

## ⚠️ 实现注意事项

### 1. SSH操作强制约束

- 若测试步骤或前置条件中需要SSH到服务器后台或虚拟机后台执行命令，**必须**调用 `sugon_web/common/ssh.py` 中封装好的公共方法

  - `ssh_vm` fixture：通过跳板机连接虚机的SSH会话
  - `ssh_host` fixture：直接SSH连接目标主机（不经过跳板机）

### 2. Fixture强制约束

- 实现测试步骤或前置条件的自动化脚本前，**必须**阅读 `sugon_web/case_specs/fixtures_index.md`
- 查阅fixture强制约束和速查表，确认框架中是否已有可复用的fixture
- **禁止**针对已有的fixture进行重复封装

### 3. 可复用Fixture参考

根据 `fixtures_index.md`，本用例可能涉及的fixture：

- `vpc` fixture：创建虚拟私有云（支持 `count` 参数批量创建）
- `vm` fixture：创建虚机（支持 `count` 参数批量创建，若引用vpc fixture则自动复用其网络和子网）
- `er_page` fixture：企业路由器页面对象（已定义于 `sugon_web/testcase/network/conftest.py`）
- `vpc_page` fixture：虚拟私有云页面对象
- `ecs_page` fixture：弹性云服务器页面对象（用于获取虚机IP等信息）
- `ops_page` fixture：运维管理页对象（用于绑定MFIP）
- `ssh_vm` fixture：通过跳板机连接虚机的SSH会话（用于执行ping命令）

### 4. 后台命令执行规范

- ping命令执行后会立即返回结果，不需要使用 `nohup` 后台执行
- ping命令示例：`ping -c 4 <目标IP>`

### 5. ER对等连接操作说明

- ER对等连接需要双向建立：ER1使用ER2的授权码建立连接，ER2使用ER1的授权码建立连接
- 授权码通过ER列表页操作栏的"生成授权码"按钮生成
- 生成授权码后需点击取消关闭弹窗，弹窗不自动关闭
- ER连接类型选择"企业路由器"时需填写授权码

### 6. ER路由表操作说明

- 路由表规则通过ER详情页"路由表"tab中的"新建路由表规则"按钮创建
- 需要选择下一跳类型为"企业路由器"，并选择对应的连接和下一跳ER
- 路由规则添加后可能需要等待1分钟左右才能生效，期间需要定时刷新列表

### 7. VPC路由表操作说明

- 添加自定义路由需要在VPC详情页的"路由表"tab中操作
- 需要断言路由规则是否添加成功，可通过目的地址在路由列表中定位并验证
- 清理时需要先删除自定义路由规则，再删除VPC

### 8. 连通性验证说明

- vm1和vm2分别位于不同的VPC中，默认情况下无法互通
- 通过ER对等连接两个ER实例、配置ER路由表和VPC路由后，两个VPC下的虚机应当可以互通
- ping验证需要双向测试（vm1→vm2 和 vm2→vm1）
- ping 4次全通才算验证通过，需要断言 packet loss 为 0%
