## 前置条件

1. 已预置VPC（如vpc1），并在VPC下创建四台虚机：ecs0、ecs1、ecs2、ecs3
2. 在vpc1下，预置负载均衡(基础版)V1实例slbv1
3. 监听器参数配置：
   - 监听器名称：tcp_8080
   - 描述：1234567890edwqWDWQ中文~
   - 协议：TCP
   - 协议端口：8080
   - 资源池名称：backend_1
   - 负载调度算法：轮询
   - 其他字段保持默认值（如不开启会话保持、不开启健康检查等）
4. 测试数据不可复用，各场景独立创建和清理

## 测试步骤

### 场景1：SLB详情页监控验证（用例414218，步骤1-6，所属模块：network）

#### 步骤1：添加资源池成员

- 操作：在slbv1详情页 -> 监听器tab下 -> 点击监听器名称tcp_8080 -> 选择资源池tab，进入资源池backend_1详情后，点击创建按钮，选择ecs1、ecs2、ecs3为该资源池的成员，对应端口为8080
- 预期：
  - 新建成员成功，资源池列表的实例名称、端口号、资源状态信息与新建资源数据一致
  - ecs1、ecs2、ecs3的资源状态为运行中

#### 步骤2：后端虚机配置（ecs1、ecs2、ecs3）

- 操作：通过 `ssh_vm` fixture 连接虚拟机后台，分别登录ecs1、ecs2、ecs3，执行如下操作
- 子步骤：
  1. 创建测试目录：
     ```bash
     cd /root && mkdir test
     ```
  2. 创建测试文件（以ecs1为例，其他虚机注意修改标识）：
     ```bash
     cd /root/test/ && echo "this is ecs1" >> index.html
     ```
  3. 启动web server（使用nohup后台执行，避免占用SSH会话）：
     ```bash
     cd /root/test/ && nohup python3 -m http.server 8080 > /dev/null 2>&1 &
     ```
  4. 轮询等待，使用 `ss -lntp | grep 8080` 命令检查web服务启动成功，最长等待60秒
- 预期：
  - 目录创建成功
  - 文件创建成功
  - web服务启动成功

#### 步骤3：进入SLB监控详情页

- 操作：在slb列表页，点击预置slbv1实例对应行，点击查看监控
- 预期：进入slbv1的监控详情页，页面正常显示

#### 步骤4：VIP访问测试（生成流量数据）

- 操作：通过 `ssh_vm` fixture 连接ecs0，多次请求此slbv1实例的网络IP（VIP），执行命令：
  ```bash
  curl http://<slbv1_vip>:8080/index.html
  ```
- 预期：tcp监听器可以正常访问，返回 "this is ecsX"

#### 步骤5：实例级别监控验证

- 操作：在slbv1的监控详情页，实时tab下查看实例tab监控曲线变化
- 预期：各图表的曲线可以正常显示，数据值不为零

#### 步骤6：监听器级别监控验证

- 操作：在slbv1的监控详情页，实时tab下查看监听器tab，选择tcp_8080监听器，检查监控曲线变化
- 预期：各图表的曲线可以正常显示，数据值不为零

### 场景2：CMS监控服务监控验证（用例414218，步骤7-10，所属模块：cms）

## ⚠️ 实现注意事项

### 1. SSH操作强制约束

- 若测试步骤或前置条件中需要SSH到服务器后台或虚拟机后台执行命令，**必须**调用 `sugon_web/common/ssh.py` 中封装好的公共方法
- 禁止在测试代码中直接使用 `paramiko`、`subprocess` 等方式建立SSH连接
- 推荐使用fixture：
  - `ssh_vm` fixture：通过跳板机连接虚机的SSH会话
  - `ssh_host` fixture：直接SSH连接目标主机（不经过跳板机）

### 2. Fixture强制约束

- 实现测试步骤或前置条件的自动化脚本前，**必须**阅读 `sugon_web/case_specs/fixtures_index.md`
- 查阅fixture强制约束和速查表，确认框架中是否已有可复用的fixture
- **禁止**针对已有的fixture进行重复封装

### 3. 可复用Fixture参考

根据 `fixtures_index.md`，本用例可能涉及的fixture：

- `vpc` fixture：创建VPC（支持count参数批量创建）
- `vm` fixture：创建虚机（支持count=4参数批量创建4台虚机，自动绑定MFIP）
- `slb` fixture：创建负载均衡实例（支持version="V1"参数）
- `lb` fixture：创建监听器实例
- `slb_page` fixture：负载均衡页对象（导航到负载均衡服务）
- `ecs_page` fixture：弹性云服务器页对象

### 4. 后台命令执行规范

- 所有需要后台长期运行的命令（如启动web server），**必须**使用 `nohup` 命令并在末尾添加 `&` 符号，避免在自动化用例执行过程中长时间占用SSH会话连接
- 示例：`nohup python3 -m http.server 8080 > /dev/null 2>&1 &`
- 启动后需轮询检查服务状态（最长60秒），确认服务正常启动后再继续后续步骤

### 5. 监控图表断言策略

- 监控图表数据验证建议采用以下策略：
  - 先检查图表元素是否存在且可见
  - 再检查数据值不为零（可通过图表数值文本或数据接口返回值验证）
  - 由于监控数据可能存在延迟，建议访问VIP生成流量后等待适当时间（如10-30秒）再检查监控数据
- 场景1（步骤5-6）在SLB详情页验证监控，场景2（步骤9-10）在CMS监控服务中验证监控，两者页面结构可能不同，需分别定位监控图表元素

### 6. 多模块切换注意事项

- 步骤1-6所属模块为network，通过SLB服务页面操作
- 步骤7-10所属模块为cms，通过URL直接进入CMS监控服务页面操作
- 步骤7进入CMS监控服务时，需要通过URL直接导航，**禁止**在测试代码中直接写死URL，应通过配置获取CMS服务地址

## 清理数据

测试完成后需要清理的资源。

### ⚠️ 清理顺序强制要求

在面对一些长流程的测试用例时，清理数据有强制的前后顺序要求，否则会删除失败。本用例的测试数据清理流程**必须**按照如下顺序执行：

1. 进入slbv1详情的监听器tab，进入tcp_8080的资源池tab，进入资源池backend_1详情页，将 ecs1、ecs2、ecs3 从资源池中移除
2. 删除监听器tcp_8080
3. 删除负载均衡实例slbv1
4. 删除虚机 ecs0~ecs3（由 vm fixture teardown 自动回收）
5. 删除 VPC vpc1（由 vpc fixture teardown 自动回收）

### 清理注意事项

- 清理顺序不可颠倒，必须严格按照上述顺序依次执行
- 如果在清理过程中某一步骤失败，需先解决该步骤的问题后再继续后续清理
- 每个清理步骤完成后应验证清理成功，再执行下一个清理步骤
- 虚机和VPC的清理由fixture的teardown机制自动完成，但需确保在此之前已完成lb、slb相关资源的清理
