# 测试用例：企业路由器-连接新建功能验证

## 基本信息

- 用例编号：5923, 412939
- 所属产品：曙光云Stack
- 一级模块：网络
- 二级模块：企业路由器

## 适配范围

### 存储适配

- 该用例不支持的存储：无

### 架构/节点限制

- 架构限制：无
- 节点要求：无

## 前置条件

1. 已预置虚拟私有云 `er-vpc1`，网段 `173.3.3.0/24`（本资源在多个场景中复用）
2. 已预置虚拟私有云 `er-vpc2`，网段 `173.3.3.0/24`（本资源在多个场景中复用）
3. 已预置HA类型企业路由器 `er-ha-autotest`（本资源在多个场景中复用）
4. 已预置非HA类型企业路由器 `er-noha-autotest`（本资源在多个场景中复用）

## 测试步骤

### 场景1：ER添加VPC连接功能验证（用例5923）

#### 步骤1：进入企业路由器列表页

- 操作：登录云平台后，依次点击：资源中心 -> 网络 -> 企业路由器
- 预期：可以正常打开企业路由器列表页

#### 步骤2：进入HA企业路由器详情页

- 操作：在ER列表页，点击前置条件中预置的HA实例 `er-ha-autotest` 名称，进入详情页
- 预期：详情页可以正常打开

#### 步骤3：切换到连接tab

- 操作：在详情页中，点击"连接"tab
- 预期：可以正常打开连接tab

#### 步骤4：添加VPC连接

- 操作：点击"添加连接"按钮，按如下内容输入：
  - 名称：`er1-vpc1-conn`（按常规输入）
  - 连接类型：默认值为"虚拟私有云"，保持不变
  - 虚拟私有云：选择前置条件中预置的 `er-vpc1`
  - 子网：选择该VPC下的子网
  - 其它字段保持默认值，点击确定
- 预期：
  - 可以正常打开连接新建弹窗
  - 可以正常输入名称
  - 默认值即为"虚拟私有云"
  - 可以正常选择VPC
  - 可以正常选择子网
  - 可以正常提交

#### 步骤5：验证连接列表

- 操作：返回连接列表，每隔20秒点击列表右上方的刷新按钮，最长等待60秒，在列表确认新增的连接是否存在
- 预期：列表可以正常显示新提交的连接，名称为 `er1-vpc1-conn`，状态为"运行中"，连接类型为"虚拟私有云"

### 场景2：ER添加ER连接功能验证（用例412939）

> 依赖：场景1（用例5923）已执行完成

#### 步骤1：进入企业路由器列表页

- 操作：登录云平台后，依次点击：资源中心 -> 网络 -> 企业路由器
- 预期：可以正常打开企业路由器列表页

#### 步骤2：为HA企业路由器生成授权码

- 操作：在ER列表页，点击前置条件中预置的HA实例 `er-ha-autotest` 对应操作栏的"生成授权码"按钮，记录生成的授权码为 `er1-code`，然后点击"取消"按钮

  - 可以正常输入名称
  - 可以正常选择"企业路由器"

  - 可以正常提交

#### 步骤6：验证HA端连接

#### 步骤7：进入非HA企业路由器连接管理

- 操作：返回ER列表页，点击 `er-noha-autotest` 对应操作栏的"管理连接"按钮

#### 步骤8：添加ER连接（非HA→HA）

- 操作：点击"添加连接"按钮，按如下内容输入：
  - 名称：`er2-er1-conn`（按常规输入）
  - 连接类型：选择"企业路由器"
  - 授权码：输入步骤2记录的 `er1-code`
  - 其它字段保持默认值，点击确定
- 预期：
  - 添加连接弹窗可以正常打开
  - 可以正常输入名称
  - 可以正常选择"企业路由器"
  - 可以正常输入授权码
  - 可以正常提交

#### 步骤9：验证非HA端连接

- 操作：返回连接列表，每隔20秒点击列表右上方的刷新按钮，最长等待60秒，在列表确认新增的连接是否存在
- 预期：列表可以正常显示新提交的连接，名称为 `er2-er1-conn`，状态为"运行中"，连接类型为"企业路由器"

## 清理数据

### 清理顺序强制要求

测试数据清理流程**必须**按照如下顺序执行：

1. 删除所有连接（先删除ER连接，再删除VPC连接）
2. 删除企业路由器实例（先删除非HA实例，再删除HA实例）
3. 删除虚拟私有云

### 清理注意事项

- 清理顺序不可颠倒，必须严格按照上述顺序依次执行
- 如果在清理过程中某一步骤失败，需先解决该步骤的问题后再继续后续清理
- 每个清理步骤完成后应验证清理成功，再执行下一个清理步骤
- 由于"测试数据是否可复用"标记为"是"，这些场景共享同一套测试数据，所有用例执行完成后统一清理

## 实现注意事项

### 1. SSH操作强制约束

- 若测试步骤或前置条件中需要SSH到服务器后台或虚拟机后台执行命令，**必须**调用 `sugon_web/common/ssh.py` 中封装好的公共方法
- 禁止在测试代码中直接使用 `paramiko`、`subprocess` 等方式建立SSH连接
- 推荐使用fixture：
  - `ssh_vm` fixture：通过跳板机连接虚机的SSH会话
  - `ssh_host` fixture：直接SSH连接目标主机（不经过跳板机）

### 2. Fixture强制约束

- 实现测试步骤或前置条件的自动化脚本前，**必须**阅读 `sugon_web/case_specs/fixtures_index.md`
- 查阅fixture强制约束和速查表，确认框架中是否已有可复用的fixture
- **禁止**针对已有的fixture进行重复封装

### 3. 可复用Fixture参考

根据 `fixtures_index.md`，本用例可能涉及的fixture：

- `vpc` fixture：创建虚拟私有云（支持count参数批量创建）
- `er_page` fixture：企业路由器页面对象（已定义于 `sugon_web/testcase/network/conftest.py`）
- 企业路由器创建：可通过 `er_page.er_create()` 方法在测试前置步骤中创建

### 4. 后台命令执行规范

- 所有需要后台长期运行的命令，**必须**使用 `nohup` 命令并在末尾添加 `&` 符号
- 示例：`nohup <command> > /dev/null 2>&1 &`

### 5. 连接类型切换说明

- 添加连接弹窗中，连接类型默认为"虚拟私有云"，选择"企业路由器"时会显示授权码输入框
- 选择"虚拟私有云"时会显示VPC和子网选择框
- 两种连接类型的表单字段不同，需要根据连接类型动态处理表单填写

### 6. 授权码获取说明

- 授权码通过列表页操作栏的"生成授权码"按钮获取
- 生成后点击"取消"按钮关闭弹窗，不复制授权码（仅记录用于后续输入）
- 授权码为一次性使用，不可重复使用

### 7. 轮询等待规范

- 连接创建后状态变为"运行中"需要一定时间
- 需每隔20秒刷新列表，最长等待60秒
- 使用 `assert_status` 或自定义轮询逻辑实现
