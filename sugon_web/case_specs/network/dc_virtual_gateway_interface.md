# 测试用例：云专线DC-虚拟网关及虚拟接口创建功能验证

## 基本信息
- 用例编号：5611、5617
- 所属产品：曙光云Stack
- 一级模块：网络
- 二级模块：云专线v1/虚拟网关、云专线v1/虚拟接口

## 适配范围

### 存储适配
- 该用例不支持的存储：无

### 架构/节点限制
- 架构限制：无
- 节点要求：无

## 前置条件

1. 已使用admin账号登录云平台
2. HA策略已开启（后端 `policy_document` 标志为true）
3. 已预置VPC（dc1_vpc1），网段13.34.34.0/24
   - 本资源在多个场景中复用
4. 已预置一个HA类型的物理连接，审批通过，vlan号为205
   - 本资源在多个场景中复用

## 测试步骤

### 场景1：虚拟网关-新建功能测试-vpc-静态路由（用例5611）

> 测试数据可复用，本场景与场景2共享同一套测试数据。

#### 步骤1：进入虚拟网关页面

- 操作：依次点击：资源中心 -> 网络 -> 云专线DC -> 虚拟网关
- 预期：可以正常进入虚拟网关页面，列表可以正常显示

#### 步骤2：创建虚拟网关

- 操作：点击"新建"按钮，在弹出的新建弹窗中按如下信息填写：
  - 网关名称：自定义字符串，如 `vgw-{random_data(length=4)}`
  - 关联模式：选择"虚拟私有云"
  - 虚拟私有云：选择预置的VPC（dc1_vpc1）
  - BGP ASN：保持为空（默认值）
  - 描述：保持为空
  - 子步骤：
    1. 填写完成后，点击"立即创建"按钮
- 预期：
  - 各字段可以正常输入/选择，字段值显示准确
  - 关联模式切换后，虚拟私有云/企业路由器字段条件渲染正确
  - 点击"立即创建"后弹窗关闭，列表自动刷新

#### 步骤3：验证列表页

- 操作：在虚拟网关列表页查看新创建的虚拟网关
- 预期：
  - 列表中包含新创建的虚拟网关
  - 名称字段显示为输入的网关名称
  - 关联模式字段显示为"虚拟私有云"
  - 资源名称字段显示为预置的VPC名称（dc1_vpc1）
  - 状态字段显示为"运行中"

#### 步骤4：验证详情页

- 操作：点击新创建的虚拟网关名称，打开详情抽屉
- 预期：
  - 详情抽屉正常展示
  - 名称、关联模式、资源名称等字段与创建时输入一致

### 场景2：虚拟接口-新建-vpc类型虚拟网关-静态路由（用例5617）

> 依赖：场景1（用例5611）已执行完成，且虚拟网关未被删除。
>
> 测试数据可复用，本场景与场景1共享同一套测试数据（同一个VPC、物理连接实例）。虚拟网关可以在场景1中创建，场景2复用；也可以在场景2中独立创建。

#### 步骤1：进入虚拟接口页面

- 操作：依次点击：资源中心 -> 网络 -> 云专线DC -> 虚拟接口
- 预期：页面可正常跳转，无报错出现

#### 步骤2：创建虚拟接口

- 操作：点击"新建"按钮，进入独立创建页面，按如下信息填写：
  - 名称：自定义字符串，如 `vif-{random_data(length=4)}`
  - 物理连接：选择前置条件中预置的HA物理连接
  - 虚拟网关：选择场景1中创建的虚拟网关（或前置条件中预置的虚拟网关）
  - 虚拟子网：选择下拉列表中的子网，如果有多个选择第1个
  - 本端网关（云端侧）：固定值，输入 `11.22.0.2/24`
  - 远端网关（用户侧）：固定值，输入 `11.22.0.3/24`
  - 路由模式：选择"静态路由"
  - 远端子网：固定值，输入 `123.12.0.0/24`
  - 描述：保持为空
  - 子步骤：
    1. 填写完成后，点击"立即创建"按钮
- 预期：
  - 各字段可以正常输入/选择，字段值显示准确
  - 虚拟网关选择后，虚拟子网字段条件渲染正确
  - 路由模式选择"静态路由"后，远端子网字段条件渲染正确
  - 点击"立即创建"后页面跳转到虚拟接口列表页

#### 步骤3：验证列表页

- 操作：在虚拟接口列表页查看新创建的虚拟接口，等待后台处理完成
- 子步骤：
  1. 页面跳转后等待约2分钟（120秒），让后台完成资源创建
  2. 刷新列表页查看状态
- 预期：
  - 列表中包含新创建的虚拟接口
  - 名称字段显示为输入的名称
  - 物理连接字段显示为选择的物理连接名称
  - 本地网关字段显示为 `11.22.0.2/24`
  - 远端网关字段显示为 `11.22.0.3/24`
  - 状态字段显示为"运行中"

## ⚠️ 实现注意事项

### 1. SSH操作强制约束
- 若测试步骤或前置条件中需要SSH到服务器后台或虚拟机后台执行命令，**必须**调用 `sugon_web/common/ssh.py` 中封装好的公共方法
- 禁止在测试代码中直接使用 `paramiko`、`subprocess` 等方式建立SSH连接
- 本用例不涉及SSH操作

### 2. Fixture强制约束
- 实现测试步骤或前置条件的自动化脚本前，**必须**阅读 `sugon_web/case_specs/fixtures_index.md`
- 查阅fixture强制约束和速查表，确认框架中是否已有可复用的fixture
- **禁止**针对已有的fixture进行重复封装

### 3. 可复用Fixture参考

根据 `fixtures_index.md`，本用例可能涉及的fixture：

- `vpc` fixture：创建VPC（支持count参数批量创建，返回name、subnet_name、cidr）
- `dc_page` fixture：云专线DC页面对象（已存在于 `testcase/network/conftest.py`）
- `page` fixture：Playwright页面对象，每个测试函数独立

### 4. Page Object 扩展要求

本用例需要在现有 `DcMixin`（`sugon_web/pages/network/dc.py`）基础上扩展以下方法：

**虚拟网关相关方法**：
- `virtual_gateway_create(name, association_mode, vpc_name)`：打开虚拟网关新建弹窗，填写信息并提交
  - 弹窗定位：`.el-dialog__wrapper:visible`（标题"新建虚拟网关"）
  - 名称：`input[placeholder="请输入名称"]`
  - 关联模式：`.el-radio-group` 内选择"虚拟私有云"
  - 虚拟私有云：`el-select` placeholder="请选择虚拟私有云"
  - 提交按钮："立即创建"
- `virtual_gateway_delete(name)`：删除指定虚拟网关
  - 操作栏点击"删除"，确认弹窗中点击"确定"
- `open_virtual_gateway_detail(name)`：点击虚拟网关名称打开详情抽屉

**虚拟接口相关方法**：
- `virtual_interface_create(name, physical_connection_name, virtual_gateway_name, local_gateway, remote_gateway, route_mode, remote_subnet)`：进入虚拟接口创建页面，填写信息并提交
  - 创建页面为独立页面（URL：`#/virtual-interface-add`）
  - 名称：`input[placeholder="请输入名称"]`
  - 物理连接：`el-select` placeholder="请选择物理连接"
  - 虚拟网关：`el-select` placeholder="请选择虚拟网关"
  - 虚拟子网：`el-select` placeholder="请选择虚拟子网"（multiple）
  - 本端网关：5个 `.ip_input` 输入框（IP四段+掩码）
  - 远端网关：5个 `.ip_input` 输入框（IP四段+掩码）
  - 路由模式：`.el-radio-group` 选择"静态路由"
  - 远端子网：`textarea`（当路由模式为static时显示）
  - 提交按钮："立即创建"
- `virtual_interface_delete(name)`：删除指定虚拟接口
  - 操作栏点击"删除"，确认弹窗中点击"确定"

### 5. 虚拟网关创建弹窗定位

虚拟网关创建使用 `el-dialog` 弹窗（`:append-to-body="true"`），弹窗定位上下文使用 `.el-dialog__wrapper:visible`。

### 6. 虚拟接口创建页面定位

虚拟接口创建为独立页面（通过路由 `/virtual-interface-add`），表单位于 `.add-box > .box` 容器内，使用 `el-form` 表单。

### 7. 网关IP输入处理

本端网关和远端网关各由5个输入框组成（IP四段+掩码位），需要使用 `.ip_input` class 定位并依次填入。

示例：输入 `11.22.0.2/24`
- 第1个 `.ip_input`：11
- 第2个 `.ip_input`：22
- 第3个 `.ip_input`：0
- 第4个 `.ip_input`：2
- 第5个 `.ip_input`：24

### 8. 下拉选项 teleport 处理

Element UI 的 `el-select-dropdown` 选项可能被 teleport 到 body，选择选项时使用 `.el-select-dropdown:visible` 作为上下文定位。

### 9. 场景依赖处理

场景2依赖场景1创建的虚拟网关。由于 pytest 中每个测试方法是独立的，采用策略B：
- 场景2独立创建虚拟网关后执行虚拟接口创建，完整生命周期后统一清理
- 每个测试方法包含完整的创建→验证→清理流程，不依赖其他测试方法的执行结果

### 10. 虚拟接口状态等待

虚拟接口创建后，后台需要时间处理。列表页验证时需要：
- 等待约2分钟（120秒）
- 刷新列表页检查状态
- 状态从"创建中"变为"运行中"

### 11. 虚拟子网选择

虚拟网关选择后，虚拟子网字段条件渲染。子网选项来自所选VPC的子网列表：
- 如果只有1个子网，直接选择
- 如果有多个子网，选择第1个

## 清理数据

### ⚠️ 清理顺序强制要求

本用例的测试数据清理流程必须按照如下顺序执行：

**场景1（虚拟网关）清理：**
1. **删除虚拟网关**：在虚拟网关列表页，点击操作栏"删除"按钮，确认删除

**场景2（虚拟接口）清理：**
1. **删除虚拟接口**：在虚拟接口列表页，点击操作栏"删除"按钮，确认删除
2. **删除虚拟网关**：在虚拟网关列表页，点击操作栏"删除"按钮，确认删除
3. **注销物理连接**：在物理连接列表页，点击操作栏"注销"按钮，确认注销

### 清理注意事项

- 清理顺序不可颠倒：必须先删除虚拟接口，再删除虚拟网关（虚拟接口依赖虚拟网关）
- 虚拟接口在"运行中"状态下可以直接删除
- 虚拟网关在虚拟接口删除后才能删除
- 每个清理步骤完成后应验证清理成功（列表中不再显示该实例）
- VPC的清理由 `vpc` fixture 的 teardown 机制自动完成
