## 基本信息

- 用例编号：3450, 3451, 3452, 3453
- 所属产品：曙光云Stack
- 一级模块：身份认证IAM
- 二级模块：组织管理-用户管理

## 适配范围

### 存储适配

- 该用例不支持的存储：无

### 架构/节点限制

- 架构限制：无
- 节点要求：无

## 前置条件

1. admin 用户已登录平台（通过 `page` fixture 自动完成登录）
2. 已存在一级组织且该组织下存在子组织（由 `iam_shared_org` 和 `iam_shared_child_org` fixture 提供，本资源在多个场景中复用）
3. 子组织下存在5个普通用户，用户信息如下：
   - 账号：`autotest-iam-` + random_data()
   - 用户名：与账号相同
   - 密码：`Keystone@1234`
   - 角色绑定：默认角色
   - 邮箱：`{username}@sugon.com`
   - 手机号：合法中国手机号格式 138XXXXXXXX
4. 本用例的测试数据不可复用，各场景独立创建和清理用户

## 测试步骤

### 场景1（用例3450）：批量修改用户状态

> 测试数据不可复用，本场景独立运行

#### 步骤1：进入用户管理页面

- 操作：admin 登录后，进入统一身份认证 IAM 页面，点击组织管理，进入用户管理 tab
- 预期：页面可正常访问，显示用户管理列表

#### 步骤2：批量禁用用户

- 操作：
  1. 在用户管理列表中勾选5个目标用户
  2. 点击"创建用户"按钮旁的"更多操作"，选择"修改用户状态"
  3. 在弹窗中设置用户状态为"禁用"，点击确定
  4. 返回列表页，查看5个用户的状态列
  5. 依次在独立浏览器上下文中用刚才禁用的5个用户登录全栈云
- 预期：
  - 弹出修改用户状态弹框
  - 绿色悬浮提示：修改用户状态成功
  - 5个用户的状态列均展示：禁用
  - 红色悬浮提示：用户未激活或已冻结，请联系管理员激活（登录失败）

#### 步骤3：批量启用用户

- 操作：
  1. 在用户管理列表中勾选刚才禁用的5个用户
  2. 点击"更多操作"，选择"修改用户状态"
  3. 设置用户状态为"启用"，点击确定
  4. 返回列表页，查看用户状态列
  5. 依次在独立浏览器上下文中用刚才启用的5个用户登录全栈云
- 预期：
  - 绿色悬浮提示：修改用户状态成功
  - 5个用户的状态列均展示：激活
  - 成功登录全栈云

## ⚠️ 实现注意事项

### 1. SSH操作强制约束

- 本用例不涉及 SSH 到服务器后台或虚拟机后台执行命令的操作

### 2. Fixture强制约束

- 实现测试步骤或前置条件的自动化脚本前，**必须**阅读 `sugon_web/case_specs/fixtures_index.md`
- 查阅 fixture 强制约束和速查表，确认框架中是否已有可复用的 fixture
- **禁止**针对已有的 fixture 进行重复封装

### 3. 可复用Fixture参考

根据 `fixtures_index.md`，本用例可能涉及的 fixture：

- `page` fixture：提供 Playwright 页面对象（自动登录为 admin）
- `iam_page` fixture：IAM 模块页面对象（定义于 `sugon_web/testcase/iam/conftest.py`）
- `iam_shared_org` fixture（package级）：提供共享的一级组织
- `iam_shared_child_org` fixture（package级）：提供共享的子组织
- `iam_batch_users` fixture（function级）：在每个测试方法中创建5个普通用户，测试结束后自动删除

### 4. 后台命令执行规范

- 本用例不涉及后台命令执行

### 5. 批量操作实现要点

- **选择用户**：使用 `select_rows_by_names(names)` 批量勾选用户行
- **更多操作**：点击"更多操作"按钮后，使用 `_click_batch_operation_option(operation)` 选择操作项
- **登录验证**：所有登录验证使用 `browser_context.new_page()` 创建独立页签，避免与 admin 会话冲突，验证完成后关闭页签
- 批量操作与单用户操作共用相同的弹窗和表单，区别在于批量操作时弹窗标题可能不同

### 6. 断言策略

- **状态修改**：页面元素断言 — 成功提示 + 列表状态字段验证
- **登录验证**：URL断言（登录成功则不含 `login`）+ 提示信息断言（登录失败则含预期错误提示）
- **列表字段**：回读列表字段与设置值对比

### 7. 测试数据策略

- 各场景独立创建5个用户，使用 `random_data()` 生成账号名避免冲突
- 用户创建使用 `create_iam_user()` helper 函数循环创建
- 批量操作用户列表通过 `iam_batch_users` fixture 提供
- 各场景执行完成后独立清理用户

## 清理数据

### ⚠️ 清理顺序强制要求

1. 删除本场景创建的5个测试用户（在用户管理列表页操作栏删除）

### 清理注意事项

- 各场景的测试数据不可复用，每个场景执行完成后需独立清理
