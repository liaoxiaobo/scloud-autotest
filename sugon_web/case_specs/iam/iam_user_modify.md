# 测试用例：IAM-组织管理-用户管理-修改用户

## 基本信息

- 用例编号：3435
- 所属产品：曙光云Stack
- 一级模块：身份认证IAM
- 二级模块：组织管理-用户管理

## 适配范围

### 存储适配

- 该用例不支持的存储：无

### 架构/节点限制

- 架构限制：无
- 节点要求：无

## 前置条件

1. admin 用户已登录云平台（通过 `page` fixture 自动完成登录）
2. 已存在一个测试用户（由用例 3434 创建，本批次共享测试数据），用户信息如下：
   - 账号：`autotest-iam-` + random_data()
   - 用户名：与账号相同
   - 角色绑定：默认角色
   - 邮箱：`{username}@sugon.com`
   - 手机号：合法中国手机号格式 1[3-9]XXXXXXXXX
   - 密码：`Keystone@1234`
3. 本资源在多个场景中复用（场景3.1~3.7共享同一个用户），所有场景执行完成后统一清理

## 测试步骤

### 场景1（用例3435-3.1）：修改用户名称

- 操作：
  1. admin 登录，进入运营侧边栏 → 统一身份认证IAM
  2. 选择左侧组织管理，点击组织结构树下子组织，点击右侧用户管理 tab 页
  3. 在用户列表中找到目标用户，点击操作列"修改用户"
  4. 在弹窗中修改用户名称为新值，点击确定
- 预期：
  - 弹窗关闭
  - 列表页用户名字段显示数据与修改后的用户名称保持一致

### 场景2（用例3435-3.2）：修改手机号

- 操作：
  1. 在用户管理 tab 页找到目标用户，点击"修改用户"
  2. 修改手机号（不可与列表中其他用户手机号一致），点击确定
- 预期：
  - 弹窗关闭
  - 列表页手机号字段显示数据与修改后的手机号保持一致

### 场景3（用例3435-3.3）：修改邮箱

- 操作：
  1. 在用户管理 tab 页找到目标用户，点击"修改用户"
  2. 修改邮箱（不可与列表中其他用户邮箱一致），点击确定
- 预期：
  - 弹窗关闭
  - 列表页邮箱字段显示数据与修改后的邮箱保持一致

### 场景4（用例3435-3.4）：修改描述信息

- 操作：
  1. 在用户管理 tab 页找到目标用户，点击"修改用户"
  2. 修改描述信息为随机内容，点击确定
- 预期：
  - 弹窗关闭
  - 列表页描述字段显示数据与修改后的描述内容保持一致

### 场景5（用例3435-3.5）：修改角色绑定

- 操作：
  1. 在用户管理 tab 页找到目标用户，点击"修改用户"
  2. 修改角色绑定：选择一个非"默认角色"的角色，点击确定
- 预期：
  - 弹窗关闭，提示修改成功

### 场景6（用例3435-3.6）：验证角色详情

- 操作：
  1. 在用户管理 tab 页，点击目标用户名称进入用户详情页
  2. 点击角色列表 tab 页
- 预期：
  - 角色名称字段显示数据与场景5绑定的角色名称一致

### 场景7（用例3435-3.7）：组合修改

- 操作：
  1. 在用户管理 tab 页找到目标用户，点击"修改用户"
  2. 同时修改用户名称、邮箱、手机号等字段信息，点击确定
- 预期：
  - 弹窗关闭
  - 列表页对应字段显示数据与修改后的值保持一致

### 场景8（用例3435-步骤4）：修改后登录验证

- 操作：
  1. 退出当前 admin 登录
  2. 使用修改后的用户账号重新登录云平台（账号为场景7修改后的账号，密码不变）
- 预期：
  - 登录云平台成功，URL 不含登录页关键词

## ⚠️ 实现注意事项

### 1. SSH操作强制约束

- 本用例不涉及 SSH 到服务器后台或虚拟机后台执行命令的操作

### 2. Fixture强制约束

- 实现测试步骤或前置条件的自动化脚本前，**必须**阅读 `sugon_web/case_specs/fixtures_index.md`
- 查阅 fixture 强制约束和速查表，确认框架中是否已有可复用的 fixture
- **禁止**针对已有的 fixture 进行重复封装

### 3. 可复用Fixture参考

根据 `fixtures_index.md`，本用例可能涉及的 fixture：

- `page` fixture：提供 Playwright 页面对象（自动登录为 admin）
- `iam_page` fixture：IAM 模块页面对象（定义于 `sugon_web/testcase/iam/conftest.py`），自动导航到统一身份认证IAM页面

### 4. 后台命令执行规范

- 本用例不涉及后台命令执行

### 5. IAM修改用户实现要点

- 修改用户弹窗与创建用户弹窗结构相似，但标题为"修改用户"而非"创建用户"
- 用户名修改后，列表中用户名列应反映最新值，后续修改/删除操作以最新名称为准
- 手机号和邮箱修改时需确保不与列表中其他用户重复
- 角色绑定修改：需选择非"默认角色"的角色
- 组合修改时需验证多个字段同时变更后列表页展示一致

### 6. 断言策略

- **场景1~4、7**：页面元素断言 — 弹窗关闭后，列表页对应字段值与修改后的值一致
- **场景5**：页面元素断言 — 弹窗关闭，成功提示出现
- **场景6**：页面元素断言 — 用户详情页角色列表 tab 中角色名称与场景5绑定角色一致
- **场景8**：URL 断言 — 新用户登录后 URL 不含登录页关键词

### 7. 测试数据策略

- 共享用例 3434 创建的测试用户（`autotest-iam-` + random_data()），不额外创建新用户
- 修改用的新值均使用 `random_data()` 生成确保唯一性
- 所有场景执行完成后统一清理该用户

## 清理数据

### ⚠️ 清理顺序强制要求

- 删除用户可能需要确认弹窗
- 本用例测试数据共享自用例 3434，所有场景执行完成后统一清理
