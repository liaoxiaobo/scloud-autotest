# 测试用例：IAM-组织管理-组织结构树-创建子组织/修改子组织

## 基本信息

- 用例编号：314、322
- 所属产品：曙光云Stack
- 一级模块：身份认证IAM
- 二级模块：组织管理-组织结构树

## 适配范围

### 存储适配

- 该用例不支持的存储：无

### 架构/节点限制

- 架构限制：无
- 节点要求：无

## 前置条件

1. admin 用户已登录云平台（通过 `page` fixture 自动完成登录）
2. 已存在一个一级组织（用于在其下创建/修改子组织）
   - 组织名称使用 `random_data()` 生成唯一值，格式：`autotest-parent-` + random_data()
   - 本资源在多个场景中复用
3. 待创建子组织参数：
   - 子组织名称：`autotest-child-` + random_data()

## 测试步骤

### 场景1（用例314）：组织结构树-创建子组织

> 依赖：前置条件中的一级组织已创建完成

#### 步骤1：进入运营-统一身份认证IAM页面

- 操作：admin登录后，进入运营侧边栏，点击"统一身份认证IAM"服务
- 预期：页面正常加载，左上角显示"统一身份认证IAM"标题

#### 步骤2：进入组织管理页面

- 操作：在IAM页面中，确认已处于组织管理（组织结构树）视图
- 预期：组织管理页面正常展示，左侧显示组织结构树，已存在的一级组织可见

#### 步骤3：点击创建子组织

- 操作：在组织结构树中找到一级组织，点击其右侧的"+"号（创建子组织按钮）
- 预期：弹出"添加组织"弹框

#### 步骤4：填写子组织名称并确认

- 操作：在弹框中输入子组织名称，点击"确定"按钮
- 预期：子组织创建成功，绿色悬浮提示创建成功

#### 步骤5：验证子组织出现在组织结构树中

- 操作：在组织结构树中展开一级组织，查看其下是否存在刚创建的子组织
- 预期：一级组织下存在刚才创建的子组织，且名称正确

### 场景2（用例322）：组织结构树-修改子组织

> 依赖：场景1（用例314）已执行完成，一级组织下已存在子组织

#### 步骤1：进入运营-统一身份认证IAM页面

- 操作：同场景1步骤1
- 预期：同场景1步骤1

#### 步骤2：进入组织管理页面

- 操作：同场景1步骤2
- 预期：同场景1步骤2

#### 步骤3：点击修改子组织

- 操作：在组织结构树中找到要修改的子组织，点击修改按钮（显示为笔的图标）
- 预期：弹出"修改组织"弹框

#### 步骤4：修改子组织名称并确认

- 操作：在弹框中输入新的组织名称，点击"确定"按钮
- 预期：绿色悬浮提示"修改组织名称成功"，组织结构树中该子组织的名称被修改为新的名称

## ⚠️ 实现注意事项

### 1. SSH操作强制约束

- 本用例不涉及 SSH 到服务器后台或虚拟机后台执行命令的操作

### 2. Fixture强制约束

- 实现测试步骤或前置条件的自动化脚本前，**必须**阅读 `sugon_web/case_specs/fixtures_index.md`
- 查阅 fixture 强制约束和速查表，确认框架中是否已有可复用的 fixture
- **禁止**针对已有的 fixture 进行重复封装

### 3. 可复用Fixture参考

根据 `fixtures_index.md`，本用例可能涉及的 fixture：

- `page` fixture：提供 Playwright 页面对象（自动登录为 admin）
- `iam_page` fixture：IAM页对象（导航到统一身份认证IAM服务）

### 4. 后台命令执行规范

- 本用例不涉及后台命令执行

### 5. IAM页面对象实现要点

- **创建子组织**：需在组织结构树中定位到父组织节点，hover或点击其右侧的"+"号按钮
  - 注意："+"号按钮可能在组织节点 hover 后才显示
  - 弹框为"添加组织"，只需填写组织名称
- **修改子组织**：需在组织结构树中定位到子组织节点，hover后点击编辑（笔）图标
  - 弹框为"修改组织"，输入新的组织名称后点击确定
- **组织树展开**：创建/修改后需要展开父组织节点以验证子组织存在/名称变更

### 6. 断言策略

- **步骤1**：页面元素断言 — 验证页面标题包含"统一身份认证IAM"
- **步骤2**：页面元素断言 — 验证组织结构树可见，一级组织存在
- **步骤3**：页面元素断言 — 验证弹框出现且标题为"添加组织"
- **步骤4**：页面元素断言 — 验证成功提示（绿色悬浮提示）
- **步骤5**：页面元素断言 — 验证组织结构树中父节点下存在子组织
- **场景2步骤3**：页面元素断言 — 验证弹框出现且标题为"修改组织"
- **场景2步骤4**：页面元素断言 — 验证成功提示 + 组织结构树中子组织名称已更新

### 7. 测试数据策略

- 一级组织名称：`autotest-parent-` + random_data()
- 子组织名称：`autotest-child-` + random_data()
- 修改后的子组织名称：`autotest-child-modified-` + random_data()
- 测试数据可复用：是，场景1和场景2共享同一套测试数据（一级组织 + 子组织）

## 清理数据

### ⚠️ 清理顺序强制要求

1. 先删除子组织
2. 再删除一级组织

### 清理注意事项

- 清理顺序不可颠倒，必须先删子组织再删父组织
- 删除组织时需要在组织结构树中找到对应节点，hover后点击删除图标
- 可能需要确认删除弹窗
- 清理前需确保以 admin 身份登录
