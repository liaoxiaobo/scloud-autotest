## 测试步骤

### 场景1（用例3436）：修改用户状态

> 依赖：前置条件中的测试用户已存在

#### 子场景1.1：禁用用户

- 操作：
  1. 进入运营-组织管理-用户管理，找到目标用户
  2. 点击操作 → "修改用户状态"
  3. 在弹窗中设置用户状态为"禁用"，点击确定
  4. 返回列表页查看用户状态列
  5. 在独立浏览器上下文中用该用户登录
- 预期：
  - 弹出修改用户状态弹窗
  - 绿色悬浮提示：修改用户状态成功
  - 用户状态列展示：禁用
  - 红色悬浮提示：用户未激活或已冻结，请联系管理员激活（登录失败）

#### 子场景1.2：启用用户

- 操作：
  1. 在同一用户上，点击操作 → "修改用户状态"
  2. 设置用户状态为"启用"，点击确定
  3. 返回列表页查看用户状态列
  4. 在独立浏览器上下文中用该用户登录
- 预期：
  - 绿色悬浮提示：修改用户状态成功
  - 用户状态列展示：激活
  - 成功登录全栈云

### 场景2（用例3437）：重置密码

> 依赖：前置条件中的测试用户已存在

- 操作：
  1. 进入组织管理-用户管理，找到目标用户
  2. 点击操作 → "重置密码"
  3. 输入新密码，点击确定
  4. 在独立浏览器上下文中用**老密码**登录
  5. 在独立浏览器上下文中用**新密码**登录
- 预期：
  - 弹出重置密码弹窗
  - 绿色悬浮提示：重置密码成功
  - 老密码登录：红色悬浮提示密码错误（登录失败）
  - 新密码登录：成功登录全栈云
- 测试数据策略：
  - 新密码：`NewPwd@5678`（满足复杂度要求）
  - 登录验证使用 `browser_context.new_page()` 创建独立页签，避免与 admin 会话冲突

### 场景3（用例3438）：设置用户过期时间

> 依赖：前置条件中的测试用户已存在

#### 子场景3.1：设置过期时间为前一天

- 操作：
  1. 进入组织管理-用户管理，找到目标用户
  2. 点击操作 → "设置用户过期时间"
  3. 选择过期时间为当前日期的前一天，点击确定
  4. 返回列表页查看过期时间列
  5. 在独立浏览器上下文中用该用户登录
- 预期：
  - 弹出设置用户过期时间弹窗
  - 过期时间列展示时间与设置时间一致
  - 红色悬浮提示：用户已过期（登录失败）

#### 子场景3.2：设置过期时间为当天

- 操作：
  1. 在同一用户上，点击操作 → "设置用户过期时间"
  2. 选择过期时间为当前日期，点击确定
  3. 返回列表页查看过期时间列
  4. 在独立浏览器上下文中用该用户登录
- 预期：
  - 过期时间列展示时间与设置时间一致
  - 成功登录云平台

## ⚠️ 实现注意事项

### 1. SSH操作强制约束

- 本用例不涉及 SSH 到服务器后台或虚拟机后台执行命令的操作

### 2. Fixture强制约束

- 实现测试步骤或前置条件的自动化脚本前，**必须**阅读 `sugon_web/case_specs/fixtures_index.md`
- 查阅 fixture 强制约束和速查表，确认框架中是否已有可复用的 fixture
- **禁止**针对已有的 fixture 进行重复封装

### 3. 可复用Fixture参考

根据 `fixtures_index.md`，本用例可能涉及的 fixture：

- `page` fixture：提供 Playwright 页面对象（自动登录为 admin）
- `iam_page` fixture：IAM 模块页面对象（定义于 `sugon_web/testcase/iam/conftest.py`）
- `test_iam_user` fixture：class级共享测试用户（定义于 `sugon_web/testcase/iam/conftest.py`）

### 4. 后台命令执行规范

- 本用例不涉及后台命令执行

### 5. 实现要点

- **修改用户状态**：操作列为"修改用户状态"，弹窗为开关/下拉选择启用或禁用
- **重置密码**：操作列为"重置密码"，弹窗含密码 + 确认密码字段
- **设置用户过期时间**：操作列为"设置用户过期时间"，弹窗含日期选择器
- **访问控制**：操作列为"访问控制"，弹窗含 IP输入、日期范围选择器、时间选择器
- 所有登录验证使用 `browser_context.new_page()` 创建独立页签，登录完成后用 `new_page.close()` 关闭
- 访问控制的"本地IP"可使用 `127.0.0.1` 作为测试值（在测试环境中 `127.0.0.1` 通常不允许登录）

### 6. 断言策略

- **状态修改**：页面元素断言 — 成功提示 + 列表状态字段验证
- **登录验证**：URL断言（登录成功则不含 `login`）+ 提示信息断言（登录失败则含预期错误提示）
- **列表字段**：`get_row_data()` 回读列表字段与设置值对比

### 7. 测试数据策略

- 共享 `test_iam_user` 创建的测试用户
- 各场景修改用户配置后使用独立页签验证登录效果
- 所有场景执行完成后由 fixture teardown 统一删除用户
