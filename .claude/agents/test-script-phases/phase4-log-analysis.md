# 阶段四：日志分析与核查

---

## 一、日志分析与核查要求

**分析范围：** 阶段一产出的需求 MD 文件定义了本次任务的自动化测试需求，请完整分析 `logs/` 目录（项目根目录下的原生日志目录）下所有测试文件的执行日志，不得遗漏任何文件。

**核查内容：** 检查每个步骤的实际执行情况是否与该需求文档中定义的流程和预期结果一致。

**teardown 段强制扫描（不得遗漏）：** 对每个测试文件日志，必须主动 `Grep` 其 teardown / cleanup / fixture finalizer 段落，列出该段所有 WARNING 与 ERROR——**严禁只核查测试步骤覆盖度而放过 teardown 告警**。

**输出形式：** 请以表格形式输出检查结果，字段包括但不限于：步骤序号、需求文档要求、实际执行的关键日志、测试结论（是否满足测试需求）；并单列一项汇总各文件 teardown 段的 WARNING/ERROR。

**MD 保护：** 分析过程中严禁修改阶段一产出的 MD 需求文档，除非确认 MD 本身存在转换错误。

---

## 二、问题分级与处理规则

**使用说明：** 将检查结果与需求 MD 文档逐项对比，判断脚本是否满足预期测试需求。

- **重要问题（须返回阶段三修复）**：核心测试步骤遗漏、关键断言缺失、测试流程与需求严重不符、**teardown 段存在 ERROR（如清理失败、SSH 断连、资源未回收）**。
- **非重要问题（可直接进入阶段五）**：日志格式不统一、Allure 步骤描述措辞差异、非关键字段值的小幅偏差、**teardown 段仅有 WARNING（须记录，随修复一并处理）**。

**判断优先级（重要问题优先）：** 若日志中同时存在重要问题和非重要问题，**一律按重要问题处理**——返回阶段三修复脚本，非重要问题随修复过程一并处理；仅在**无重要问题**时，方可直接进入阶段五。

**完成标志：** 日志分析完成，每个步骤与需求一致、teardown 段已扫描并分级，或已确认非重要问题并记录。
